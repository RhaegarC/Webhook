# 01 — Foundation

Status: **Not started** · [00-mission-1-sprint.md](00-mission-1-sprint.md)
Source: [PRD](../PRD.md) — §§4, 5, 6.2, 6.4, 6.6; Decisions #5, #6, #8, #10, #11, #14.

## Summary

Everything the other features stand on: a single project that builds, a database that exists with
the right schema, and a host that refuses to start in a misconfigured state.

Three of these are security-relevant rather than structural, and they are the reason this feature
is not just scaffolding. **Fail-fast on missing secrets** closes a fail-open hole that has no symptom
when it is open (PRD §5.1). **Removing `UseHttpsRedirection()`** prevents a silent, total delivery
failure once the tunnel lands in feature 06. **The startup write probe** converts the Docker volume
ownership hazard from a mysterious runtime death into an immediate, unambiguous one (PRD §6.3).

## Story

As the operator, I want a service that starts only when it is correctly configured and can actually
write to its database, so that misconfiguration surfaces immediately instead of as missing webhooks
weeks later.

## Dependencies

None. This is the first feature.

## Acceptance criteria

- [ ] `Microsoft.EntityFrameworkCore.Sqlite`, `Microsoft.EntityFrameworkCore.Design`, and
      `Microsoft.Extensions.Diagnostics.HealthChecks` referenced at **10.0.12**, matching the existing
      `Microsoft.AspNetCore.OpenApi` pin (verified available on nuget.org)
- [ ] `src/Webhook.Api.Test/` created with xunit + `Microsoft.AspNetCore.Mvc.Testing` 10.0.12, mirroring
      `TrailBlaze.Api.Test.csproj`'s package set and `<Using Include="Xunit" />`
- [ ] Both projects registered in [src/Webhook.Api.slnx](../../src/Webhook.Api.slnx)
- [ ] `WebhookDelivery` entity matching [PRD §4.1](../PRD.md#41-schema) exactly — no extra columns, no
      omissions. Non-obvious requirements, each with its rationale in [PRD §4.2](../PRD.md#42-rationale-for-non-obvious-choices):
  - [ ] `Id` is a surrogate `long` primary key, **not** `DeliveryId`
  - [ ] `DeliveryId` carries a **unique index**
  - [ ] `Action` is **nullable**
  - [ ] `RepositoryFullName` and `CreatedOn` carry indexes
  - [ ] `RepositoryId` is present alongside `RepositoryFullName`
  - [ ] `CreatedOn` is `DateTimeOffset`, written in **UTC**, every time — SQLite stores it as ISO-8601
        `TEXT` and it sorts correctly only under a uniform offset
- [ ] Initial migration generated (`dotnet ef migrations add InitialCreate`), applied at startup via
      `Database.Migrate()` in a try/catch
- [ ] Connection opened with `journal_mode=WAL`, `synchronous=NORMAL`, `foreign_keys=ON`, and a
      `busy_timeout` (PRD §6.2). WAL is persistent in the DB header; the other three are per-connection
- [ ] **No background writer thread, queue, or channel** — a local `INSERT` is sub-millisecond, and
      async machinery here would add a drop-on-`docker stop` failure mode for no benefit (PRD §6.2)
- [ ] `app.UseHttpsRedirection()` **removed** (PRD §6.4). This is not tidying: Cloudflare forwards
      plain HTTP to the origin, so the middleware issues a `307` and the webhook silently never arrives
- [ ] `UseForwardedHeaders` honoring `X-Forwarded-Proto` and `X-Forwarded-For`, registered **first** in
      the pipeline, so the app correctly understands it is behind TLS
- [ ] `WeatherForecast.cs` and `WeatherForecastController.cs` deleted — an unauthenticated public
      endpoint is worse than untidy in a service about to face the internet
- [ ] **Startup validation fails fast** if the webhook secret, API key, or database path is missing or
      blank (SEC-3). The trap this closes: `${WEBHOOK_SECRET:-}` yields an **empty string**, not null;
      `Encoding.UTF8.GetBytes("")` succeeds, so the HMAC is computed over a known-empty key and anyone
      who guesses "the secret is empty" forges valid signatures. It fails **open**
- [ ] **Startup write probe** attempts a real write to the data directory and throws on failure,
      logging the resolved database path (PRD §6.3)
- [ ] `public partial class Program { }` at the bottom of `Program.cs` — `WebApplicationFactory<Program>`
      cannot reach the `internal` type generated by top-level statements without it
- [ ] `WebhookApiFactory` in the test project, mirroring `TrailBlazeApiFactory` (settings dictionary +
      `UseSetting` overrides), pointing each test at its **own temporary SQLite file** — not `:memory:`,
      which requires holding a connection open for the database's lifetime and sidesteps the WAL
      configuration under test

## Tests (TDD)

- Integration (`Webhook.Api.Test`):
  - startup **throws** when `Webhook:Secret` is blank, and when it is absent (the empty-string case and
    the null case are different bugs; assert both)
  - startup **throws** when the API key is blank
  - the host starts successfully with all secrets present
  - the migration produces a `WebhookDeliveries` table with the unique index on `DeliveryId`
  - `PRAGMA journal_mode` returns `wal` on a live connection
  - a round-tripped `CreatedOn` comes back equal and in UTC

## Notes / non-goals

- **No `ReceivedAt` column.** The ingest path is synchronous, so "request arrived" and "row created"
  are the same instant. Two columns holding the same value is a latent bug awaiting a wrong filter
  (PRD §4.3). If a second timestamp is ever genuinely needed, the meaningful distinction is
  `CreatedOn` (our clock) versus the event's own time from the payload — not arrival versus insert.
- **No retention or pruning** (Decision #11). `CreatedOn` is indexed so retention stays cheap to add
  in Mission 2; adding it later needs `DELETE` **plus** `VACUUM`, because deleting rows does not shrink
  a SQLite file (PRD §4.4).
- **No layered project split** (Decision #14).
- **Not the query API, the ingest endpoint, or health.** Those are 02–04. This feature ends when the
  host starts, validates, migrates, and can be instantiated in a test.
